# Debrief design

All of Debrief's design diagrams on one page, from the big picture down to individual flows. Each image
is exported from its editable draw.io source (linked under the image) with
[`scripts/export-diagrams.sh`](../scripts/export-diagrams.sh); the sources are generated by the scripts in
[`diagrams/src`](diagrams/src/README.md), so change the generator, regenerate and re-export. The style rules are
in [diagrams/STYLE.md](diagrams/STYLE.md) (the suite spec lives in Paddock), the reasoning behind the
design in the [architecture decision records](adr/), and the prose overview in
[architecture.md](architecture.md). Large subjects are split into several diagrams of at most 1600 × 1200 pixels, numbered "1 of n".

Contents: [Overview](#overview) · [C4 model](#c4-model) · [Deployment](#deployment) ·
[Use cases](#use-cases) · [Domain and plugin API](#domain-and-plugin-api) · [Flows](#flows) ·
[States](#states)

## Overview

Many sources and collectors, one Rust engine with a DuckDB store, Rust plugins in their own sandboxed processes, and a workbench that shows
and shares what the engine computes.

![Debrief at a glance](diagrams/debrief-overview.svg)

## Flows

### Ingesting a file

From a path to events, in two parts: reading a file into records (locked-file retries, archives and their limits, the parser library’s choice, the importer under panic containment, every failure listed as unrecognised) and turning records into events (import window, extractors, pipeline, markers, the writer).

![Ingest: from a file to records](diagrams/svg/uml-activity-ingest-read.svg)

Source: [uml-activity-ingest-read.drawio](diagrams/uml-activity-ingest-read.drawio)

![Ingest: from records to events](diagrams/svg/uml-activity-ingest-events.svg)

Source: [uml-activity-ingest-events.drawio](diagrams/uml-activity-ingest-events.drawio)

### Opening a folder

`open_paths` to `Ingest::open`: the shell checks the paths and runs the import as a job, the UI follows its progress and can cancel, and the store worker imports in parallel into Parquet segments and the full-text index.

![Open a folder: from the UI to the import job](diagrams/svg/uml-seq-open-folder.svg)

Source: [uml-seq-open-folder.drawio](diagrams/uml-seq-open-folder.drawio)

![Open a folder: the import in the store worker](diagrams/svg/uml-seq-open-folder-worker.svg)

Source: [uml-seq-open-folder-worker.drawio](diagrams/uml-seq-open-folder-worker.drawio)

### Opening a video

A recording becomes events: the pinned FFmpeg runtime (downloaded, self-tested), sandboxed probe and frame passes, a pure frame selection, alignment to the logs, vision descriptions, and the frames source the importer reads.

### Watched folders

A polling thread feeds folder snapshots to a pure state machine; files import as ordinary jobs and a new known issue is announced once (ADR [0048](adr/0048-watched-folders.md)). The state diagram under States shows one file’s life.

![Watched folder sequence](diagrams/svg/uml-seq-watched-folder.svg)

Source: [uml-seq-watched-folder.drawio](diagrams/uml-seq-watched-folder.drawio)

### The command line

`debrief analyze outliers` end to end: the CLI starts the same store worker as the app, imports through the ports and runs the pure outlier analysis over the `Query` port (ADR [0044](adr/0044-headless-command-line.md), [0045](adr/0045-error-outliers.md)).
