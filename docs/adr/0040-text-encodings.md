# 40. Text encodings of source files

- Status: accepted (2026-10-22)
- Date: 2026-10-22
- Related: ADR 0014 (streaming import, file plan), ADR 0026 (parsers), AGENTS.md (parse don't validate, bounded
  resources, parsers never panic)

## Context

The file plan knew UTF-8 and UTF-16 (with a byte-order mark, or little-endian without). Logs from Japanese, Chinese,
Korean and Russian systems, Windows-125x code pages and BOM-less big-endian UTF-16 were decoded as lossy UTF-8.

## Decision

1. **Detection is part of the file plan** (`ingest::encoding`): a byte-order mark; UTF-16 without one (zero bytes, or
   aligned UTF-16 newlines); ASCII and (almost) valid UTF-8; otherwise `chardetng` guesses among `encoding_rs`'s legacy
   encodings (Shift_JIS, GBK/gb18030, EUC-KR, Big5, EUC-JP, windows-125x...). Both crates are MIT OR Apache-2.0 and
   `encoding_rs` was already in the lockfile. The sniff window is the first 64 KiB.
2. **Legacy encodings are ASCII-compatible byte streams.** `0x0A` never occurs inside their multi-byte characters, so
   lines split on bytes exactly as for UTF-8 and byte offsets stay exact. Encodings that are not (ISO-2022-JP, HZ, the
   replacement encoding) are not offered.
3. **The result has a confidence (0 to 100) and an origin** (`bom`, `detected`, `profile`, `manual`) and is stored per
   source (`source_encodings`, keyed by path, no format bump). A guess is never presented as certain.
4. **Overrides.** The profile key `[files] encoding` (`auto` or a label) is the default; the user can pick an encoding for
   one source (`Ingest::set_source_encoding`), which records a `manual` row and reads the file again; the row outlives
   reloads and reopens and is dropped by "Automatic". An unknown label is refused with what to use. A profile key change is
   a parsing change (the sources are read again).
5. **Samples** `samples/encodings/` are generated by `samples/generate.py` from invented text and excluded from the
   corpus tests that compare stores with the in-memory reference.
